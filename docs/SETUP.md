# Установка и первичная настройка

## Зависимости

Установите Python 3.12+, uv и Bambu Studio из официального дистрибутива. Для живой сцены Blender нужен включенный аддон с локальным мостом, доступным этой машине. Экспорт должен читать текущую сцену, включая несохраненные изменения. Закрытый файл `.blend` не заменяет живую сцену.

Если Blender MCP еще не установлен, используемый в проверке пакет предлагает `uvx mcp-for-blender install-addon`. После установки включите аддон `Interface: MCP for Blender` в Preferences / Add-ons и нажмите `Start MCP Server`. В конфигурации MCP укажите `command="uvx"`, `args=["mcp-for-blender"]`. Уже работающее подключение обновлять ради этой установки не нужно. Доступность `execute_blender_code` и точные имена установленного аддона следует проверить перед экспортом.

Из папки проекта:

```powershell
uv venv
uv pip install -e ".[dev]"
.\.venv\Scripts\Activate.ps1
bambu-workflow configure
bambu-workflow doctor
bambu-workflow install-codex
```

`configure` создает конфигурацию пользователя, но откажется перезаписывать существующий файл. `doctor` отдельно проверяет наличие исполняемого файла слайсера и чтение MQTT/FTPS каждого принтера. Он не выполняет тестовую печать и не заменяет проверку CLI слайсинга или экспорта Blender. `install-codex` добавляет сервер в Codex с резервной копией конфигурации.

Все команды принимают общий параметр перед подкомандой: `bambu-workflow --config C:\path\config.json doctor`.

## Принтер A1 mini

Сверьте модель с экраном и серийным номером. A1 и A1 mini имеют разные размеры и профили. Запишите IP, серийный номер, прошивку и LAN access code. Проверьте наличие исправной microSD.

Версия MCP 0.1.1 аппаратно проверена на A1 mini с прошивкой `01.08.01.00`: полный запуск из Blender, подготовка принтера и первый слой. Это не требует обновлять прошивку другого владельца до этой версии.

В A1 mini прошивка `01.05.00.00` от 03.06.2025 добавила Authorization Control. Для прямого стороннего управления на таких прошивках нужен Developer Mode. Обновлять или понижать прошивку для установки MCP автоматически не нужно.

Если требуется включить режим, выполните на экране принтера:

1. Откройте `Setting`, затем `LAN Only Mode`.
2. Включите `LAN Only Mode`.
3. Включите `Developer Mode`.
4. Прочитайте предупреждение, отметьте `I confirm reading and understanding the Important Notice above`, нажмите `Enable`.

LAN Only отключает связь с Bambu Cloud и Bambu Handy. Developer Mode открывает локальные MQTT, FTP и видеопоток; Bambu не предоставляет поддержку этих протоколов. Используйте доверенную локальную сеть. MCP не переключает режим и не принимает предупреждение за владельца.

Точные пункты могут зависеть от языка и прошивки. Если переключателя нет, сначала сверьте текущую версию с [историей A1 mini](https://wiki.bambulab.com/en/a1-mini/manual/a1-mini-firmware-release-history) и [официальной инструкцией](https://wiki.bambulab.com/en/knowledge-sharing/enable-developer-mode).

## Конфигурация и секреты

По умолчанию файл находится в `%LOCALAPPDATA%\BambuWorkflow\config.json`, а состояние заданий рядом в `state`. Другой файл задается переменной `BAMBU_WORKFLOW_CONFIG`.

Каждый принтер имеет отдельный `id`, `model`, `host`, `serial`. Вызовы печати должны явно указывать `printer_id`. Для другого бренда потребуется отдельный адаптер.

Код доступа хранится через keyring: service `bambu-workflow`, ключ `secret_ref` из записи принтера. Альтернатива: `access_code_env` с именем переменной окружения. Значение секретной переменной передается процессу MCP через настройки Codex. Не помещайте секрет в пример конфигурации, Git, журналы или командную строку.

Текущий мастер создает `tls_verify=false`, совместимый с самоподписанным сертификатом принтера. Это не проверка сертификата удостоверяющим центром. При необходимости настройте `tls_ca_file` либо `tls_fingerprint` из независимо проверенного сертификата. Подключение не меняет системное хранилище сертификатов.

Сверьте установленное сопло, материал, способ подачи и пластину. Указанный пользователем PETG не подтверждает текущую катушку. Пустой AMS не означает отсутствие внешней подачи. Неизвестный тип и остаток материала остаются неизвестными до подтверждения.

Путь к слайсеру задается `slicer.executable`, при необходимости корень профилей: `slicer.profile_root`. Явные профили задаются путями в `slicer.profiles.machine`, `slicer.profiles.process`, `slicer.profiles.filament`. Выбирается настоящий профиль `Bambu Lab A1 mini` с нужным соплом, разрешаются `inherits` и `include`, итоговые настройки сохраняются. Профиль другого принтера переименовывать нельзя.

Подготовка сейчас ограничена одним материалом на пластину: PLA, PETG или TPU. Поддержанные пластины для нового слайсинга: `textured_plate` и `hot_plate`. Для уже нарезанного 3MF номер пластины задается в `slicer.plate`, начиная с 1. Новый слайсинг геометрии создает пластину 1. Per-object настройки, модификаторы и отрицательные объемы проекта 3MF отклоняются, если их нельзя сохранить.

В `blender.command` и `blender.args` укажите запуск уже используемого Blender MCP с инструментом `execute_blender_code`. Модель должна быть в Object Mode. `selection` принимает `{"objects":["имя"]}`, `{"object":"имя"}` или `{"collection":"имя"}`. Без selection используются выделенные видимые объекты. `user_prompt` должен содержать фактический текст поручения пользователя. При единицах сцены `NONE` задайте проверенный коэффициент `blender.mm_per_unit`. Например, 1 допустимо только если одна единица этой сцены действительно равна 1 мм.

## Первое задание

Подготовка небольшой тестовой модели разрешена разработкой. Аппаратный запуск требует отдельного поручения пользователя. Сначала подготовьте файл и покажите размеры, принтер, материал, пластину и оценки слайсера.

После освобождения принтера пользователь проверяет стол и дает команду на тест. `mark_bed_ready` сохраняет проверку физически свободного стола на 30 минут и один старт. `start_prepared` использует уже подготовленный файл. Затем нужно увидеть свежую телеметрию с идентичностью этого задания, этап подготовки и начало печати.

## Диагностика

| Симптом | Проверка и следующий шаг |
| --- | --- |
| Есть состояние, управление отклоняется | Сверить Developer Mode на экране. Подписка MQTT не доказывает право управления. HMS `0500_0500_0001_0007` связан с отклонением проверки команды. |
| FTPS подключается, файл не передается | Проверить SD, место, TLS data channel и разрыв передачи. Повторить только безопасную загрузку уникального файла после проверки частичного результата. |
| Новая MQTT-сессия недоступна | Проверить отдельно TCP 8883 и TLS. В проверенном окружении множество старых сессий мониторинга сопровождалось TLS reset нового клиента; после освобождения избыточной сессии соединение заработало. Универсальный лимит клиентов не установлен. Сначала определить владельцев соединений, не прерывать печать и не перезагружать принтер ради диагностики. |
| Слайсер завершился с ошибкой | Открыть сохраненный журнал задания. Сверить полные профили, версию CLI, область печати и сообщения самого слайсера. |
| Потерян ответ после старта | Использовать `job_status`. На реальной приемке принтер начал подготовку и печать без полученного PUBACK; это подтверждено новой телеметрией. Не создавать новый request_id и не повторять старт. |
| Камера занята или нет кадра | Проверить видеопоток в Bambu Studio и отдельное соединение камеры. Успех MQTT не подтверждает камеру. |
| MCP перезапущен | Найти задание по сохраненному ID и выполнить сверку. Не удалять базу состояния ради повторного запуска. |

Причина физической ошибки должна быть устранена человеком. MCP не очищает HMS и не возобновляет печать автоматически.

Подключение stdio описано в [README](../README.md) и [официальной документации Codex](https://developers.openai.com/codex/mcp/).
