# Как вызвать MCP и навык

MCP `bambu_workflow` выполняет проверки, экспорт, слайсинг и управление сохраненными заданиями. Навык `bambu-print` задает правила разговора и выбор действия по риску. Он дополнителен к MCP: серверные блокировки действуют при любом способе вызова. Такое разделение соответствует [официальной документации OpenAI о навыках и MCP](https://developers.openai.com/plugins/concepts/skills).

## Постоянная установка

Для новой установки в пользовательский каталог из актуальной документации Codex выполните из распакованного релиза:

```powershell
.\scripts\install.ps1 -InstallSkill -SkillRoot (Join-Path $env:USERPROFILE '.agents\skills')
```

Установщик помещает пакет и отдельное окружение Python в `%LOCALAPPDATA%\BambuWorkflow\app\0.2.0`, навык целиком копирует из `skills/bambu-print` в выбранный каталог с резервной копией прежней версии. Конфигурацию Codex установщик сам не переключает. Для уже используемого совместимого каталога можно вызвать `scripts\install.ps1 -InstallSkill` без `-SkillRoot`.

Для новой установки после завершения установщика:

```powershell
$runtimePython = Join-Path $env:LOCALAPPDATA 'BambuWorkflow\app\0.2.0\.venv\Scripts\python.exe'
& $runtimePython -m bambu_workflow.cli configure
& $runtimePython -m bambu_workflow.cli install-codex
```

`configure` нужен один раз и не перезаписывает существующие настройки. Конфигурация принтера и keyring находятся вне программы. Запись `mcp_servers.bambu_workflow` сохраняется в конфигурации Codex, stdio-процесс запускается клиентом. Поддержка stdio, `config.toml` и `codex mcp list` описана в [официальной документации MCP](https://developers.openai.com/codex/mcp/).

Без `-SkillRoot` установщик использует `$CODEX_HOME/skills/bambu-print`, по умолчанию `%USERPROFILE%\.codex\skills\bambu-print`. Поддерживаемая копия в проекте: `skills/bambu-print`. В актуальной общей документации пользовательским каталогом назван `%USERPROFILE%\.agents\skills`, а для проекта `.agents/skills` внутри репозитория. Используйте один каталог, который обнаруживает целевой клиент, без двух одноименных установленных копий. [Официальная документация навыков](https://learn.chatgpt.com/docs/build-skills)

После изменения MCP откройте новый чат или перезагрузите подключение. Изменения навыков Codex обнаруживает автоматически; если навык не появился, перезапустите клиент. Наличие папки в исходниках само по себе не подключает MCP.

## Обычные команды в чате

Без явного упоминания навыка:

```text
Отправь выделенную модель Blender на печать через bambu_workflow.
Подготовь коллекцию Print к печати, пока не запускай.
Покажи состояние задания JOB_ID.
```

С явным выбором навыка:

```text
$bambu-print Отправь выделенную модель Blender на печать.
$bambu-print Подготовь коллекцию Print и покажи риски без запуска.
```

Навык допускает автоматический выбор по подходящему запросу. Для явного вызова CLI/IDE документация указывает `$bambu-print` либо `/skills`; в ChatGPT выбор навыка доступен через `@`. Если клиент показывает список, выберите `Bambu Print`. Упоминание навыка само по себе не поручает физическую печать. [Способы вызова в документации OpenAI](https://learn.chatgpt.com/docs/build-skills)

Для Blender нужно выделение или название объекта/коллекции активной сцены. Если в ней есть только `Print.001`, а глобальная `Print` принадлежит другой сцене, используется фактическая коллекция текущей сцены. При нескольких подходящих коллекциях агент уточнит выбор. При нескольких настроенных устройствах укажите принтер. Первый запуск требует известных материала, сопла, пластины и физически свободного стола. Пустой стол отмечается после наблюдения человеком, на один старт и не более 30 минут.

## Три результата проверки

| Уровень | Что происходит |
| --- | --- |
| `critical` | Печать блокируется до устранения причины. Отсутствие ответа не разрешает запуск, масштабирование или обход проверки. |
| `medium` | Исходный вариант проходит обязательные проверки. Агент предлагает необязательное улучшение и дает примерно 60 секунд на ответ. Без ответа продолжает уже порученную печать исходного варианта, сохраняя геометрию и настройки. |
| `clear` | Уже порученная печать запускается после проверки готовности, без повторного общего подтверждения. |

Medium не разрешает автоматически менять отверстия, посадки, стенки, масштаб, поддержки или предложенный профиль. Для изменения нужен явный ответ на конкретное предложение, затем новая проверка копии. Если поручена только подготовка, любой уровень заканчивается без запуска. Занятый принтер не отменяется и не превращается в молчаливую очередь на будущее.

`print_assessment(job_id)` возвращает уровень и причины. `print_model` при medium оставляет `prepared`/`review_pending`; в сервере нет фонового таймера запуска. Продолжение исходного варианта после ожидания выполняет агент через `start_prepared`, опираясь на ранее данное поручение печатать. Критические условия этим инструментом не обходятся.

## Прямые инструменты и CLI

Основные MCP-инструменты: `list_printers`, `prepare_print`, `print_model`, `print_assessment`, `job_status`, `start_prepared`, `mark_bed_ready`. Схемы текущей версии нужно обнаружить перед вызовом. Подготовка возвращает `job_id`, дальнейший результат читается отдельно.

Из установленного окружения доступны:

```powershell
& $runtimePython -m bambu_workflow.cli prepare --printer workshop-mini --request-id part-001 --file C:\models\part.stl
& $runtimePython -m bambu_workflow.cli job JOB_ID
```

Для безопасной проверки каталога MCP без обращения к принтеру есть:

```powershell
& $runtimePython scripts\call_mcp.py --python $runtimePython
```

Без `--tool` этот клиент только инициализирует сервер и выводит имена инструментов; восстановление старых worker отключено. Явные принтерные инструменты этой гарантии не имеют. JSON-аргументы большого вызова можно передать через `--arguments-file`; используйте оригинальный `user_prompt` и стабильный `request_id`.

Повтор исходного запроса использует те же аргументы и ID. При `start_uncertain` читается свежий `job_status`, старт повторно не отправляется. Подробности: [RECOVERY.md](RECOVERY.md). Статусы загрузки и команды не равны началу печати; нужны совпадающее задание и признаки реального слоя.

Навык проверен штатным validator и независимыми сценариями: medium с молчанием, critical с превышением стола, подготовка без запуска при занятом принтере и выбор `Print.001` текущей сцены при чужой глобальной `Print`. Это проверка поведения инструкции без принтерных вызовов.
