# Design review, 2026-11-06

An additional implementation review identified four integration defects: the public auto support alias was not accepted by the slicer, legacy feed bindings did not verify imported executable product/color, a worker could retain stale nozzle facts, and profile caps did not bound actual startup extrusion. These were corrected with alias handling, required complete sliced-import palettes, configuration refresh at both dispatch checks, and conservative executable-flow validation. Regression tests exercise changed spools and same-size nozzle replacements before/during upload, mandatory review, pure-E purges and modal/conditional flow.

Version 0.4.0 was planned with five independent advisors and checked by two independent cross-reviewers. They used the same request and local/public source packet. Their analysis did not contact printers, start prints, upload private models, or execute upstream Support Fins code. Conclusions were assessed against source and executable acceptance; reviewer agreement alone is not evidence of functionality.

## Findings retained

| Finding | Resulting decision |
| --- | --- |
| Normalized STL erases painting, object settings, and material structure | Keep single-material geometry reslicing separate from a validated pre-sliced 3MF route; unsupported features are refused rather than flattened |
| Polymer-only checks can accept a substituted PETG product/color | Bind exact preset/product, supplied profile/color, and AMS unit/slot facts to the prepared job; reread before start |
| Thin fin contacts may disappear in slicing while aggregate mesh checks pass | Require artifact-bound actual-layer review for manual/finned/tilted, imported sliced, and multicolor jobs; inspect contacts/islands explicitly |
| Custom nozzle identity is richer than diameter | Record manufacturer/model/material/flow/geometry compatibility and calibrated limits; expire human confirmation and invalidate changed configurations |
| Multiple same-model printers are still different devices | Select explicit configured printer ID and retain device identity; do not redirect a prepared job through a changed default |
| Fusion/QymCAD neutral exports avoid unstable native parsing | Retain native sources, record provenance/units/control dimensions, and verify exports; no native adapter is claimed |
| QymCAD README lagged behind releases | Use versioned 3MF release evidence, including the all-bodies fix, and require a real export fixture before claiming installed-app acceptance |
| Support Fins can return successful partial output | Keep per-object reports/warnings, pin the external CLI, preserve originals, and retain unsupported-region blockers or Bambu Studio handoff |

## Changes after cross-review

The two reviewers emphasized that ordinary preparation must remain useful without imposing the complex-support gate on every model. Required actual-layer review cannot be cleared by a medium-warning timeout. Silence can only preserve an already printable original variant under an existing print instruction; it never authorizes fins, tilt, repair, a changed profile, or disabling native supports.

The reviewers also rejected treating removal of a one-material guard as multicolor support. The sliced route must validate the executable G-code, entire palette, used tools/filaments, feed mapping, purge envelope, and artifact review. Painting and unsupported modifiers must not disappear through a fallback. Native Bambu Studio project preparation followed by inspected sliced import is the practical route where headless project preservation is not implemented.

Printer setup must support distinct devices and the installed English skill must include its progressive references. Personal defaults remain local. Fresh source checking corrected P2S AMS compatibility, hotend material/flow choices, and QymCAD release behavior. No P2S/AMS/custom-nozzle/finned hardware claim was added.

## Acceptance and unresolved evidence

Software acceptance covers exact-profile slicing, negative configuration/material/review cases, durable job identity, and mock transport behavior. The dated [validation record](VALIDATION.md) must supply the exact checks actually completed; this review does not substitute for them.

Physical P2S/AMS routing, custom-nozzle calibration/clearance, fin contact/removal behavior, and installed Fusion/QymCAD versioned export fixtures remain separate acceptance work. They require real hardware/application evidence and, for a physical print, an explicit print instruction and fresh bed/nozzle facts. Automated preflight cannot guarantee strength, adhesion, or prevention of every future defect.
