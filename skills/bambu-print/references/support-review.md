# Support and diagonal-print review

Checked 2026-11-06. Choose `support_mode` explicitly when the workflow depends on a particular support strategy:

| Mode | Meaning |
| --- | --- |
| `auto` | Ordinary profile-driven preparation; it does not promise complete support coverage. |
| `native` | Supports generated by the selected slicer configuration. |
| `baked_fins` | Modeled fin geometry already exists in the derivative; mandatory layer review. |
| `manual` | Manually designed or edited supports in an already sliced Studio file; mandatory layer review. Unsliced manual-support projects remain in Studio. |

A plate-diagonal Z rotation changes its XY envelope. An X/Y tilt changes bed contact, overhangs, support demand, layer loading, and potentially dimensional behavior. Do not treat those rotations as equivalent. Preserve an explicitly requested orientation. Propose a tilt or geometry change concretely and obtain explicit authorization before generating it.

## Optional Support Fins tool

[Support Fins / printfins](https://printfins.com/) creates breakaway fin supports. Reviewed release: [v1.0.5](https://github.com/gittrahan/support-fins/tree/514549694e816999a5e4c6674829eba7ea852019), immutable commit `514549694e816999a5e4c6674829eba7ea852019`. The Git tag was checked against the remote on 2026-11-06. The external tool is MIT-licensed and not bundled. Its [CLI documentation](https://github.com/gittrahan/support-fins/blob/514549694e816999a5e4c6674829eba7ea852019/plugins/cli/README.md) describes ordinary exports, project preservation, report fields, and limitations. Do not assume later `main` or `plugins-latest` has the same behavior.

Use the workflow's `generate_support_fins` only when its local CLI is configured and checksum-pinned. This adapter accepts a separate millimeter STL only and outputs a receipt-bound unsliced 3MF for Bambu Studio; it does not automatically flatten or slice that project. It prepares a derivative and does not authorize or start a print. Pass the exact input, output folder, approved pose, actual nozzle diameter, and regular layer height. Record `geometry_change_authorized=true` only after the user explicitly approved this derivative. Keep the original and record source/output hashes, tool revision, settings, and warnings. Installation is documented in the package's `docs/INSTALL.md`; do not run or download a mutable latest tool as a fallback.

The upstream `--preserve-project` path aims to keep project structure, placement, settings, and painting while adding support objects and discarding stale slice artifacts. It is separate from this adapter's STL-only generation route and has no local end-to-end acceptance here. Preservation support in the external tool does not imply this MCP can reslice every such project. Use Bambu Studio and the supported sliced-3MF route when unsupported modifiers/painting or multiple materials must survive. Never flatten them silently. Native supports may remain enabled in upstream project mode; disable them only for an explicitly approved fins workflow, after checking the selected objects and keeping the original project.

Exit code 0 can coexist with skipped objects, unsupported overhangs, or pieces starting in midair. Inspect structured object reports, warnings, and output hashes. A saved 3MF or a `no_supports` result is not evidence of printable coverage. Missing/mixed upstream nozzle metadata can fall back to 0.4 mm with warnings; always supply the actual diameter and verify the report.

## Mandatory actual-layer evidence

Prepare with `require_layer_review=true`. Inspect the current artifact in a real sliced preview or a tool that shows the executable G-code layers. In addition to first/middle/top layers, inspect:

- Every new island and the layers where a fin, tine, or native support meets the model.
- Continuous extrusion from support base/pad to contact; thin contact geometry may disappear during slicing.
- Holes, fits, walls, bridges, material assignments, and whether supports can be removed without damaging functional features.
- Full print envelope including pads, fins, brim, purge tower, travel, and applicable toolhead/sequential-clearance constraints.

Expected tine contact is local geometry to inspect. It does not justify globally ignoring collision or G-code path-conflict warnings. Unexplained toolhead collisions, unsupported islands, lost features, or unverified contacts block launch regardless of a mesh-level `clear` result. Automatic geometry checks do not simulate all physical collisions or certify adhesion/strength.

Record only a review that actually occurred:

```json
{
  "job_id": "RETURNED_JOB_ID",
  "artifact_sha256": "SHA256_OF_CURRENT_PREPARED_ARTIFACT",
  "review": {
    "reviewer": "actual reviewer",
    "evidence": "Actual preview/layer references and observations",
    "layers": [1, 2, 35, 36, 90],
    "checks": {
      "first_layer": true,
      "critical_features": true,
      "support_contacts": true,
      "unsupported_islands": true,
      "material_assignments": true,
      "removability": true
    }
  }
}
```

Replace the example layer list with the actual one-based layers inspected, including layer 1 and all critical contact/feature transitions. Optional `evidence_paths` can name existing absolute preview/report files, whose hashes are retained. Here `unsupported_islands=true` means the reviewer checked for unsupported islands and found no unresolved blocker. Do not set checks true to satisfy a form. Reslicing, changing supports, pose, nozzle, material, or the artifact requires a new review. A later coupon can establish contact/removal behavior for a specific material/nozzle/layer setup only after a separate physical print instruction; software tests cannot supply that evidence.
